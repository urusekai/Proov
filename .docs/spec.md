# MVP Spec

## 포함 기능
- 회원가입/로그인
- 비로그인 공개 문제 풀이
- PR URL 직접 입력
- 공개 GitHub PR 정보 수집
- diff 필터링/제한
- GPT-5.4 문제 생성
- PR 기반 객관식 3문항 생성
- 문항 단위 풀이
- 자동 채점
- 짧은 해설과 관련 파일명 표시
- 로그인 사용자 풀이 기록 저장
- 풀이 기록 목록/상세 조회(문항별 최신 1건)
- 사이트 제공 문제 목록
- 마이페이지에서 프로필 이미지와 닉네임 수정
- 비밀번호 변경
- 회원탈퇴

## 제외 기능
- GitHub 계정 연동
- 비공개 repository 분석
- PR 목록 자동 불러오기
- 문제 5문항
- 티어/랭킹/공개 프로필
- 결제/팀/기업용 기능
- 서술형/단답형
- 코드 라인 단위 근거

## 제한 정책
- 변경 파일 최대 8개
- 전체 diff 최대 12,000자
- 파일당 patch 최대 3,000자
- PR 설명 최대 1,000자
- 필터링 후 변경 파일이 없으면 변경 내용 부족으로 처리
- 필터링 후 실제 변경 줄 수(additions + deletions 합산) 5줄 미만이면 변경 내용 부족으로 처리
- lock, 이미지, 바이너리, build, coverage, minified 파일 제외

## 인증 정책
- 비로그인 사용자는 사이트에서 제공하는 공개 문제를 선택해 풀이할 수 있다.
- PR URL 입력 및 문제 생성은 로그인이 필요하다. 비로그인 사용자가 `/problem-sets/new`에 접근하면 `/auth/login?redirect=...`으로 리다이렉트한다.
- 비로그인 풀이 결과는 기록으로 저장하지 않는다. 결과 화면에서 "로그인하여 저장" CTA를 표시한다.
- 로그인 사용자가 결과 화면에 접근하면 저장 CTA 대신 "풀이 기록이 저장되었습니다." 메시지를 표시한다.
- 결과를 저장하거나 이후 기록에서 다시 보려면 로그인해야 한다.
- 로그인 후에는 랜딩을 대시보드처럼 사용하며, "새 문제 만들기"·"문제 목록 보기" CTA, 날짜 기반 랜덤 추천 문제 3개, 최근 풀이 기록(최신 3건)을 보여준다. PR 입력창은 `/problem-sets/new`에만 있다.
- 이미 로그인한 상태에서 `/auth/login`, `/auth/signup`에 접근하면 `redirect` 파라미터가 있으면 해당 경로로, 없으면 홈으로 리다이렉트한다.
- `/history`와 `/history/[submissionId]`는 로그인 필수. 비로그인 접근 시 `/auth/login?redirect=...`으로 리다이렉트한다.

## 문제와 PR 묶음
- PR은 문제 생성, 출처, diff 맥락을 보관하는 묶음이다.
- 사용자에게 노출되는 기본 단위는 개별 문항이다.
- AI는 PR 1개에서 객관식 3문항을 생성하고, 각 문항은 같은 ProblemSet에 연결된다.
- 사이트 제공 문제와 사용자가 PR URL로 직접 생성한 문제는 같은 ProblemSet/Question 구조를 사용한다.
- 사이트 제공 문제는 공개 목록에 문항 단위로 노출되며, 직접 생성한 문제는 기본적으로 목록에 노출하지 않는다.
- 목록 카드의 제목은 개별 문항의 짧은 title을 사용하고, 실제 질문 문장(question)은 풀이 화면에서 표시한다.
- 문항 title은 한국어 명사구 스타일로 작성하며, 질문형 문장이나 정답을 드러내는 표현을 쓰지 않는다.
- PR 제목, PR URL, pull number, repository는 출처 맥락을 위한 보조 메타데이터로 표시한다.
- 목록 카드에는 문항 title, 문항 난이도, 문항 태그, 언어/프레임워크/라이브러리 태그, 관련 파일명, repository, PR 메타데이터를 표시한다. 요약(summary)은 카드에 노출하지 않는다.
- 문항 난이도는 `BEGINNER`, `INTERMEDIATE`, `ADVANCED` 중 하나를 사용하고, 사용자 화면에는 쉬움/보통/어려움으로 표시한다.
- 같은 PR에서 나온 다른 문항은 결과 화면 또는 풀이 화면에서 이어풀기 대상으로 제공할 수 있다.

## 태그 모델
- 태그는 세트 태그와 문항 태그로 구분한다.
- 세트 태그는 ProblemSet에 종속되며, 언어, 프레임워크, 라이브러리, 도메인/주제를 표현한다.
- 문항 태그는 Question에 종속되며, Code Behavior/Data Flow 같은 코드 이해 유형을 표현한다.
- 문제 목록에서 난이도 필터는 문항 난이도를 기준으로 하고, 언어/프레임워크 필터는 세트 태그를 기준으로 한다.
- 라이브러리/주제/문제 유형은 카드의 태그로 노출하되, MVP Lite 목록 필터에는 포함하지 않는다.
- 필터 결과는 개별 Question 카드로 표시한다.
- 초기 구현은 ProblemSet의 `languageTags`, `frameworkTags`, `libraryTags`, `topicTags` 배열과 Question의 `tag`, `difficulty` 필드를 사용한다.
- 태그 관리와 검색이 복잡해지면 `tags`, `problem_set_tags`, `question_tags` 테이블로 정규화한다.

## 문제 태그
- 문제 태그는 문항 태그를 의미한다.
- 문제 난이도도 문항에 종속된다.
- 문제 태그는 출제 전에 강제 배정하지 않는다.
- AI가 diff에 근거한 문제 3개를 먼저 생성한 뒤, 각 문제에 가장 적절한 태그를 사후 부여한다.
- 같은 태그가 여러 문제에 반복되어도 허용한다.
- 태그 다양성보다 문제 품질과 diff 근거성을 우선한다.
- 사용자 화면에는 내부 enum이 아니라 영어 라벨을 표시한다.

| 내부 값 | 사용자 표시 | 용도 |
| --- | --- | --- |
| CODE_BEHAVIOR | Code Behavior | 변경된 코드의 실행 결과와 조건 분기 이해 |
| DATA_FLOW | Data Flow | 값, props, state, request/response 흐름 이해 |
| STATE_CHANGE | State Change | 상태값, 캐시, 저장 데이터의 변화 이해 |
| SIDE_EFFECT | Side Effect | 변경이 다른 흐름이나 엣지 케이스에 줄 영향 추론 |
| ERROR_HANDLING | Error Handling | 예외, 실패 응답, fallback, retry 처리 이해 |
| API_CONTRACT | API Contract | 요청/응답 형식, 함수 시그니처, 외부 인터페이스 변화 이해 |
| TEST_INTENT | Test Intent | 추가/수정된 테스트가 검증하는 동작 이해 |
| LOGIC_ERROR | Logic Error | 논리 오류 수정 또는 잠재적 논리 문제 이해 |
| STRUCTURAL_CHANGE | Structural Change | 구조 분리, 책임 이동, 이름 변경, 중복 제거 이해 |
| CONFIG_CHANGE | Config Change | 환경 설정, 빌드 설정, 옵션 변화 이해 |

## 화면
- 랜딩
- 로그인/회원가입
- 마이페이지
- 문제 목록
- 새 풀이 시작(`/problem-sets/new`): PR 입력 및 문제 생성 대기. 생성 완료 후 `/my-problems`로 이동하며, 바로 풀이 화면으로 가지 않는다.
- 문제 풀이(`/problem-sets/[id]?question=...`): 공개 문제와 PR 생성 문제를 같은 화면으로 단일 문항 풀이
- 결과(`/problem-sets/[id]/result`)
- 기록 목록
- 기록 상세

## 채점
- 기본 풀이 단위는 단일 문항이다.
- 단일 문항 결과는 정답/오답으로 표시하고, 저장 시 score는 정답 100, 오답 0으로 기록한다.
- 여러 문항을 한 번에 제출하는 확장 흐름에서는 정답률을 0/33/67/100 점수로 환산할 수 있다.

## 풀이 기록
- 기록 목록과 대시보드 최근 기록은 **문항(question) 단위**로 관리한다.
- 로그인 사용자가 이미 푼 문항을 다시 제출하면 새 row를 쌓지 않고, 해당 문항의 기존 submission을 최신 결과로 갱신한다.
- 목록 API는 문항별 최신 1건만 반환하며, 과거에 중복 저장된 row가 있어도 화면·통계에는 반영하지 않는다.
- 기록 상세 URL은 갱신된 submission id를 유지한다.
