# MVP Spec

## 포함 기능
- 회원가입/로그인
- 비로그인 PR 문제 체험
- PR URL 직접 입력
- 공개 GitHub PR 정보 수집
- diff 필터링/제한
- GPT-5.4 문제 생성
- 객관식 3문항 풀이
- 자동 채점
- 짧은 해설과 관련 파일명 표시
- 로그인 사용자 풀이 기록 저장
- 풀이 기록 목록/상세 조회
- 사이트 제공 문제 세트 목록

## 제외 기능
- GitHub 계정 연동
- 비공개 repository 분석
- PR 목록 자동 불러오기
- 문제 5문항
- 티어/랭킹/공개 프로필
- 결제/팀/기업용 기능
- 서술형/단답형
- 코드 라인 단위 근거

## 제한 정책
- 변경 파일 최대 8개
- 전체 diff 최대 12,000자
- 파일당 patch 최대 3,000자
- PR 설명 최대 1,000자
- 필터링 후 전체 diff 200자 미만이면 변경 내용 부족으로 처리
- 필터링 후 변경 파일이 없으면 변경 내용 부족으로 처리
- lock, 이미지, 바이너리, build, coverage, minified 파일 제외

## 인증 정책
- 비로그인 사용자는 PR URL 입력, 문제 생성, 문제 풀이, 결과 확인까지 진행할 수 있다.
- 비로그인 사용자는 사이트에서 제공하는 공개 문제 세트를 선택해 풀이할 수 있다.
- 비로그인 결과는 풀이 기록으로 저장하지 않는다.
- 결과를 저장하거나 이후 기록에서 다시 보려면 로그인해야 한다.
- 로그인 후에는 랜딩을 대시보드처럼 사용하며, 새 PR 입력과 최근 풀이 기록을 먼저 보여준다.

## 문제 세트
- 기본 노출 단위는 개별 문항이 아니라 PR 기반 3문항 문제 세트다.
- 사이트 제공 문제와 사용자가 PR URL로 직접 생성한 문제는 같은 ProblemSet 구조를 사용한다.
- 사이트 제공 문제는 공개 목록에 노출되며, 직접 생성한 문제는 기본적으로 목록에 노출하지 않는다.
- 목록 카드의 대표 제목은 PR 제목이 아니라 학습 주제를 설명하는 별도 제목을 사용한다.
- 목록 카드의 제목과 요약은 정답 조건이나 변경 결론을 직접 드러내지 않고, 읽게 될 코드 영역과 학습 주제만 넓게 설명한다.
- 풀이 전 목록에서는 PR 제목, PR URL, pull number를 숨긴다.
- repository는 출처 맥락을 위해 약하게 표시할 수 있다.
- PR 제목, PR URL, pull number는 결과 화면이나 출처 확인 영역에서만 표시한다.
- 목록 카드에는 제목, 요약, 세트 태그, 포함된 문제 유형 태그, 난이도, 예상 소요 시간, repository를 표시한다.
- 난이도는 `BEGINNER`, `INTERMEDIATE`, `ADVANCED` 중 하나를 사용하고, 사용자 화면에는 영어 라벨로 표시한다.
- 단일 문항은 독립 풀이 단위로 노출하지 않는다. 카테고리/필터는 문제 세트 목록에서 세트 태그와 포함된 문항 태그를 조합해 제공한다.

## 태그 모델
- 태그는 세트 태그와 문항 태그로 구분한다.
- 세트 태그는 ProblemSet에 종속되며, 언어, 프레임워크, 라이브러리, 도메인/주제를 표현한다.
- 문항 태그는 Question에 종속되며, Code Behavior/Data Flow 같은 코드 이해 유형을 표현한다.
- 문제 세트 목록에서 언어/프레임워크/라이브러리/주제 필터는 세트 태그를 기준으로 한다.
- 문제 세트 목록에서 문제 유형 필터는 세트에 포함된 문항 태그를 기준으로 한다.
- 필터 결과는 개별 문항이 아니라 ProblemSet 카드로 표시한다.
- 초기 구현은 ProblemSet의 `languageTags`, `frameworkTags`, `libraryTags`, `topicTags` 배열과 Question의 `tag` 필드를 사용한다.
- 태그 관리와 검색이 복잡해지면 `tags`, `problem_set_tags`, `question_tags` 테이블로 정규화한다.

## 문제 태그
- 문제 태그는 문항 태그를 의미한다.
- 문제 태그는 출제 전에 강제 배정하지 않는다.
- AI가 diff에 근거한 문제 3개를 먼저 생성한 뒤, 각 문제에 가장 적절한 태그를 사후 부여한다.
- 같은 태그가 여러 문제에 반복되어도 허용한다.
- 태그 다양성보다 문제 품질과 diff 근거성을 우선한다.
- 사용자 화면에는 내부 enum이 아니라 영어 라벨을 표시한다.

| 내부 값 | 사용자 표시 | 용도 |
| --- | --- | --- |
| CODE_BEHAVIOR | Code Behavior | 변경된 코드의 실행 결과와 조건 분기 이해 |
| DATA_FLOW | Data Flow | 값, props, state, request/response 흐름 이해 |
| STATE_CHANGE | State Change | 상태값, 캐시, 저장 데이터의 변화 이해 |
| SIDE_EFFECT | Side Effect | 변경이 다른 흐름이나 엣지 케이스에 줄 영향 추론 |
| ERROR_HANDLING | Error Handling | 예외, 실패 응답, fallback, retry 처리 이해 |
| API_CONTRACT | API Contract | 요청/응답 형식, 함수 시그니처, 외부 인터페이스 변화 이해 |
| TEST_INTENT | Test Intent | 추가/수정된 테스트가 검증하는 동작 이해 |
| LOGIC_ERROR | Logic Error | 논리 오류 수정 또는 잠재적 논리 문제 이해 |
| STRUCTURAL_CHANGE | Structural Change | 구조 분리, 책임 이동, 이름 변경, 중복 제거 이해 |
| CONFIG_CHANGE | Config Change | 환경 설정, 빌드 설정, 옵션 변화 이해 |

## 화면
- 랜딩
- 로그인/회원가입
- 문제 세트 목록
- 새 풀이 시작: PR 입력
- 문제 생성 대기
- 문제 풀이
- 결과
- 기록 목록
- 기록 상세

## 채점
- 총 3문항
- 1개 정답: 33점
- 2개 정답: 67점
- 3개 정답: 100점
