# Design Guide

## 방향
Proov는 PR 기반 코드 이해력 학습 SaaS다. 화면은 장식보다 문제, 코드 맥락, 결과가 먼저 보이게 만든다.

- 업무 도구처럼 차분하고 명확하게 구성한다.
- 불필요한 카드 중첩과 과한 장식은 피한다.
- diff, 파일명, 태그 등 개발자 친화적인 시각 언어를 사용한다.

## Layout
- 랜딩: 풀 너비 히어로 + 최대 `1248px` 중앙 정렬 섹션. 각 섹션은 일반적인 SaaS 랜딩페이지와 같이 뷰포트를 채우는 화면 단위(`min-h-screen` 혹은 `min-h-[calc(100vh-64px)]`)로 구성하고 수직 중앙 정렬(flex-center)하여 전달력을 극대화한다.
- 공통 헤더: 페이지 본문이 풀폭을 쓰는 화면과 동일하게 `max-w-none` + 반응형 좌우 padding을 사용한다.
- 공통 푸터: 랜딩 섹션과 동일하게 `1248px` 중앙 정렬 컨테이너를 사용한다.
- 공통 헤더 메뉴는 MVP IA 기준으로 `새 풀이`, `풀이 기록`, `로그인`, `회원가입`을 사용한다. 독립 페이지가 아닌 문제/결과는 전역 메뉴로 노출하지 않는다.
- 서비스 화면: `288px` 사이드바 + 메인 영역을 기본으로 한다.
- 문제 풀이처럼 코드 맥락과 풀이 상태를 함께 봐야 하는 화면은 최대폭 제한을 두지 않고, 좌측 diff와 우측 문제 패널의 2컬럼 구성을 허용한다.
- 기본 거터 `24px`, 모바일 여백 `16px`, 섹션 간격 `80px`.

## Color

| --- | --- | --- |
| Primary | `#5323e6` | 브랜드/강조 텍스트 |
| Accent | `#6c47ff` | CTA, 활성 상태, 진행바 |
| Background | `#f5f4ff` | 기본 배경 (기존 #f8f7ff에서 카드와의 대비를 높이기 위해 개선) |

| Lavender Tint | `#e2dfff` | 약한 강조 및 카드 테두리 (확실한 경계 구분을 위해 기존 #f0eeff에서 개선) |
| Text | `#1c1b1b` | 주요 텍스트 |

## Typography
- UI/본문: `Pretendard`
- 코드/파일명/경로/diff: `Geist Mono`
- 히어로: `48px / 700`, 모바일 `32px / 700`
- 섹션 제목: `24px / 600`
- 본문: `16px / 400`
- 보조 텍스트: `14px / 400`
- 코드: `14px / Geist Mono`

## Components

### Cards
- Radius `12px`
- 배경 `#ffffff`
- 기본 shadow: `0 3px 6px -1px rgba(83, 35, 230, 0.08), 0 1px 3px -1px rgba(0, 0, 0, 0.06)` (기존의 단단하고 적게 퍼지는 스타일을 살리고, 연한 보라색 브랜드 틴트를 가미하여 깔끔하게 마감한 그림자)
- 강조 shadow: `0 8px 12px -2px rgba(83, 35, 230, 0.14), 0 2px 4px -1px rgba(0, 0, 0, 0.08)` (구조와 면을 단단히 잡아주는 컴팩트한 강조 그림자)
- 배경에 그라데이션이나 격자무늬 패턴 등의 장식 요소를 넣지 않고, 랜딩페이지 전체를 `#f5f4ff` (Background) 단색 배경으로 통일하여 정보를 차분하고 명확하게 보여줍니다.
- 페이지 전체를 카드처럼 감싸거나 카드 안에 카드를 넣지 않는다.

### Buttons
- Primary: `#6c47ff` 배경, 흰색 텍스트, `8px` radius.
- Outline/Ghost: 보라색 테두리 또는 텍스트.
- hover/focus/disabled 상태를 명확히 구분한다.
- 선택지처럼 반복되는 버튼은 선택 상태를 단일 border와 약한 배경으로 표시하고, 이중 테두리처럼 보이는 ring은 피한다.

### Inputs
- 둥근 모서리와 단색 테두리를 사용한다.
- focus 시 `#6c47ff` border/ring을 적용한다.
- PR URL 입력은 충분한 폭과 명확한 placeholder를 가진다.

### Tags
- 내부 enum 대신 영어 라벨을 표시한다.
- 예: `Code Behavior`, `Data Flow`, `Error Handling`, `API Contract`
- 문제 본문보다 약하게 보이게 한다.
- 문제 풀이와 결과 화면의 태그 라벨은 동일한 보라색 틴트 스타일을 사용한다.

## Diff UI
| 상태 | 배경 | 텍스트 |
| --- | --- | --- |
| Added | `#ecfdf5` | `#10b981` |
| Removed | `#fef2f2` | `#ef4444` |

- diff, 파일명, 경로는 `Geist Mono`를 사용한다.
- `+`, `-`, 수치, 라벨 등 색상 외 신호를 함께 쓴다.
- diff 영역은 밝은 테마의 단일 패널로 구성하고, 중첩 카드/과한 테두리/어두운 코드 박스를 피한다.
- 긴 diff는 패널 내부 커스텀 스크롤로 처리하며 페이지 전체 가로폭이나 세로 스크롤을 밀어내지 않는다.
- 파일 탭에서 파일명을 표시하므로 `diff --git`, `new file mode`, `index`, `---`, `+++` 같은 Git 메타 라인은 화면에서 숨긴다.
- MVP에서는 관련 파일명/경로만 표시하고 코드 라인 근거는 표시하지 않는다.

## Screen Rules
- 랜딩: PR 기반 문제 생성과 공개 PR URL 입력 흐름을 첫 화면에서 전달한다.
- PR 입력: 공개 GitHub PR URL 입력을 중심에 둔다.
- 문제 풀이: 공통 헤더를 유지하고, 연습 중단/실제 GitHub PR 이동 같은 세션 액션은 PR 메타 섹션에 둔다. 좌측에는 파일별 Git diff 탭과 선택된 파일의 diff를 넓게 배치하고, 우측에는 넉넉한 폭의 문제 패널, 3분할 진행바, 이전/다음 이동, 제출 버튼을 배치한다.
- 문제 풀이 PC 레이아웃은 헤더 아래 영역을 뷰포트 높이에 맞추고, 좌측 diff 패널과 우측 문제 패널의 세로 크기를 맞춘다. 문제 패널의 이동/제출 버튼은 패널 하단에 고정 배치하며, 페이지 전체 스크롤 대신 diff 본문만 스크롤한다.
- 문제 생성 대기와 결과 화면은 `1248px` 컨테이너를 사용하되 단순 확장하지 않는다. 로딩 화면은 상태와 처리 단계를 2컬럼으로 배치하고, 결과 화면은 점수 요약을 넓게 보여준 뒤 문항별 분석을 문제당 1행으로 배치하며 AI 해설은 각 행의 오른쪽에 충분한 폭으로 둔다.
- 결과: 점수는 `33`, `67`, `100` 중 하나이며 정답/선택/해설/관련 파일을 표시한다.
- 기록: 로그인 사용자는 자기 기록만 조회한다.

## States
- Hover: 연한 라벤더 배경 또는 shadow 증가.
- Focus: `#6c47ff` ring.
- Loading: PR 분석/문제 생성 진행 상태 표시.
- Empty: dashed border 또는 연한 배경.
- Error: 원인과 다음 행동을 짧게 안내.

## Accessibility
- 색상만으로 정답/오답/추가/삭제를 구분하지 않는다.
- 키보드 focus 상태를 명확히 표시한다.
- 모바일에서 버튼/선택지 텍스트가 넘치지 않아야 한다.
