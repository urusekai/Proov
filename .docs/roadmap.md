# Roadmap

개발 전 기준을 빠르게 확인하기 위한 실행 계획서다. 상세 정책은 `spec.md`, AI 생성 규칙은 `ai.md`, DB/API 계약은 `db-api.md`, UI 기준은 `design.md`와 프로토타입을 따른다.

## 핵심 원칙
- 비로그인 사용자는 공개 문제 풀이, 결과 확인만 가능하다.
- PR URL 입력과 문제 생성은 로그인이 필요하다. 비로그인 사용자는 `/auth/login?redirect=...`으로 리다이렉트한다.
- 로그인은 문제 생성, 결과 저장, 기록 목록/상세 조회가 필요할 때 요구한다.
- 로그인 후 `/`는 대시보드로 전환: 환영 문구 + "새 문제 만들기"·"문제 목록 보기" CTA, 오늘의 추천 문제(날짜 기반 랜덤 3개 카드), 최근 풀이 기록(최신 3건), 전체 기록 링크. PR 입력창은 `/problem-sets/new`에만 존재한다.
- 이미 로그인한 상태에서 `/auth/login`, `/auth/signup`에 접근하면 `redirect` 파라미터가 있으면 해당 경로로, 없으면 홈(`/`)으로 리다이렉트한다.
- 사이트는 미리 생성해 공개한 문제 목록을 제공한다. PR은 생성/출처/맥락 단위이고, 사용자 노출/풀이/기록 단위는 개별 문항이다.
- 문제 목록에서는 개별 문항의 짧은 title을 대표 제목으로 보여주고, 실제 질문 문장과 PR 학습 제목은 풀이/출처 맥락으로 분리한다. 요약(summary)은 카드에 노출하지 않는다.
- 태그는 두 레벨로 관리한다. 언어/프레임워크/라이브러리/주제 태그는 문제 세트에 종속되고, Code Behavior/Data Flow 같은 문제 유형 태그와 난이도는 개별 문항에 종속된다. MVP Lite 목록 필터는 현재 UI 기준으로 문항 난이도/언어/프레임워크만 제공한다.
- 결과 화면에서 비로그인 사용자에게 저장 CTA를 노출한다. 로그인 사용자에게는 저장 완료 메시지를 표시한다.
- GitHub OAuth, 비공개 repo, 5문항, 티어/랭킹/공개 프로필, 결제, 서술형, 코드 라인 근거는 MVP에서 제외한다.

## 구현 지침
- API key와 service role key는 서버에서만 사용한다.
- OpenAI 호출 전 PR URL 검증, 제외 파일 필터링, diff 제한, 변경 내용 부족 여부를 먼저 검사한다.
- 제한 수치와 기능 범위는 `spec.md`를 따른다.
- AI 생성 규칙과 Zod 검증은 `ai.md`를 따른다.
- 풀이 전 문제 조회 응답에는 정답과 해설을 포함하지 않는다.
- 사용자는 자기 기록만 조회할 수 있어야 한다.

## IA
```txt
/
  로그인 전: 소개 + 문제 생성 로그인 CTA + 비교 카드 + 큐레이션 문제 미리보기
  로그인 후: 추천 문제 + 최근 기록 + CTA

/auth/login, /auth/signup
  이메일 인증

/mypage
  프로필 이미지/닉네임 수정, 비밀번호 변경, 회원탈퇴

/problem-sets
  사이트 제공 문제 목록 (CURATED + PUBLIC 문제 세트를 문항 단위로 표시)

/problem-sets/new
  PR URL 입력, 분석 및 문제 생성 진행 상태. 생성 완료 후 /my-problems로 이동

/problem-sets/[id]?question=...
  공개 문제와 PR 생성 문제가 공통으로 사용하는 객관식 단일 문항 풀이

/problem-sets/[id]/result
  채점 결과, 해설, 태그, 로그인 저장 CTA

/my-problems
  로그인 사용자가 PR URL로 생성한 내 문제 세트 목록 (문항 단위 카드, 세트 단위 삭제)
  로그인 필수

/history
  로그인 사용자 풀이 기록 목록

/history/[submissionId]
  로그인 사용자 풀이 기록 상세
```

## 화면 체크리스트
- Landing (비로그인): 설득 히어로, How it works, 기존 코딩테스트 vs Proov 비교 카드, 큐레이션 문제 세트 3개 미리보기.
- Landing (로그인 후): 환영 문구 + "새 문제 만들기"·"문제 목록 보기" CTA 버튼, 오늘의 추천 문제(날짜 기반 랜덤 3개 카드), 최근 풀이 기록 3건, 전체 기록 링크.
- Auth: 이메일, 비밀번호, 제출, 전환 링크, 오류 메시지. 이미 로그인된 경우 `redirect` 파라미터가 있으면 해당 경로로, 없으면 홈 리다이렉트.
- Problem List: 문항 title, 언어/프레임워크/라이브러리 태그, 문제 유형 태그, 문항 난이도, 관련 파일명, repository, PR 메타, 난이도/언어/프레임워크 필터, 최신순/난이도순 정렬.
- New Problem Set: PR URL 입력, 문제 생성 버튼, 처리 단계 진행 표시(5단계), PR URL 표시, 에러 화면(재입력). 비로그인 접근 시 로그인 리다이렉트. 생성 완료 후 `/my-problems`로 이동.
- My Problems: 내가 생성한 문제 세트를 문항 단위 카드로 표시. 문제 세트 단위 삭제(확인 모달). 로그인 필수, 비로그인 접근 시 로그인 리다이렉트.
- Problem Solving: PR 컨텍스트(저장소/PR번호/제목), 좌측 diff 탭뷰, 우측 문제 패널(같은 PR 문항 이동/태그/문항/선택지/제출 버튼).
- Result: 정답/오답 판정, 문제 유형 태그, 기술 스택 태그, PR 정보, 제출 문항의 정오답·해설·관련 파일, 같은 PR 다른 문제 CTA. 비로그인이면 저장 CTA, 로그인이면 저장 완료 메시지.
- My Page: 계정 요약, 프로필 이미지/닉네임 수정, 이메일 확인, 비밀번호 변경, 회원탈퇴. 비로그인 접근 시 로그인 리다이렉트.
- History List: 푼 문항 수/강한 유형/약한 유형/연속 풀이일 요약, 난이도별 푼 문항, 유형별 정답률, 기록 목록(문항·저장소·난이도·정답 여부·날짜), 최신순/점수순 정렬. 비로그인 접근 시 로그인 리다이렉트.
- History Detail: 결과 화면과 동일 구성(정답 여부·태그·PR정보·제출 문항 정오답·해설). 비로그인 접근 시 로그인 리다이렉트.

## 구현 순서 (완료)
1. 프로젝트 초기 세팅: Next.js, TypeScript, Tailwind, Supabase, env, 기본 레이아웃.
2. 인증과 권한: 회원가입, 로그인, 로그아웃, 마이페이지, 기록 저장/조회 보호.
3. 문제 목록: 공개 문항 조회, 카드형 목록, 언어/프레임워크/문항 난이도/정렬 UI. 큐레이션 데이터 폴백 지원.
4. PR 입력 흐름: 로그인 필수, 비로그인 시 로그인 페이지 리다이렉트, URL 파싱/검증, 생성 대기 화면.
5. GitHub PR 수집: 메타데이터, 파일 diff, 제외 파일 필터링, diff 제한.
6. AI 문제 생성: GPT-5.4 호출, Zod 검증, 문제/태그/목록 노출 메타데이터 저장, 생성 실패 처리. 생성 완료 후 `/my-problems`로 이동.
7. 내가 만든 문제 목록/삭제: `/my-problems` 화면, `GET /api/my-problem-sets`, `DELETE /api/problem-sets/:id`.
8. 풀이/채점: 문제 조회, 선택 UI, 제출 검증, 로그인 저장과 비로그인 preview 분기.
9. 결과/기록: 결과 화면, 저장 CTA, 기록 목록/상세, RLS와 소유권 검증.

## 완료 기준 (달성)
- 비로그인으로 공개 문제 풀이, 결과 확인이 가능하다.
- 로그인 사용자만 PR URL을 입력해 문제를 생성할 수 있다.
- 사용자는 사이트에서 제공하는 공개 문제 목록을 보고 바로 풀이를 시작할 수 있다.
- 로그인 사용자는 내가 만든 문제 세트 목록(`/my-problems`)을 보고 삭제할 수 있다.
- 로그인 사용자는 결과를 저장하고 기록 목록/상세를 볼 수 있다.
- 제한 초과 PR과 문제 생성 불가 PR은 OpenAI 호출 전에 차단된다.
- AI 문제는 diff가 지지하는 만큼 1~3문항 생성, 문항별 사후 태그/난이도, Zod 검증 규칙을 만족한다.
- 다른 사용자의 기록 및 문제 세트에 접근할 수 없다.
- Vercel 배포가 가능하다.

## 후순위
- 추천 학습, 상세 통계, 랭킹, 티어, 공개 프로필, GitHub OAuth, 비공개 repo 분석, PR 전체 리뷰 모드.
